一根会说话的弹簧

在弹珠机里，你能"看见"自己用了多大力——而且是真实的物理回弹

眼睛代替数字

力度条是"仪表盘思维"。弹簧是"身体思维"——你看见它被压缩，本能就知道力量有多大。看颜色就知道力度，不需要识字、不需要说明书。

真实物理回弹

松手后弹簧不是线性滑回原位，而是阻尼振荡——过冲再回弹，3~4个可见周期后平稳停下。就像捏一根真正的弹簧，释放后它会"弹过头再回来"。零张图片，每个像素都是算出来的。

蓄力决定球从哪进场

你按得越用力，球飞得越高、进场越靠左；按得轻，球进场越靠右。力气大小 = 落点位置，你上手一按就能感觉到。这背后对应着"力度互补"的设计——不同力气把九个格子自然铺满（详见「进化」一章）。

三种颜色，三个故事

灰蓝色 = 还没用力 金黄色 = 正在蓄力，越来越"烫" 橙红色 = 力度不够，弹不上去。满蓄力后持续按住不再是死寂——每隔一小会儿轻响一声"还顶着"的确认音，消除"是不是没在蓄力了"的疑惑。

一颗球的三段旅程

笔直升空 → 贴弧面转向 → 自由落袋，全程看得见、全程没人干预

第一段：笔直往上冲

球离手后不横着飞、不斜着窜，先老老实实竖直上升，像火箭点火升空。这一步没有任何横向的小动作，你看到的就是纯粹的"往上冲"。

第二段：贴弧面慢慢转弯

球冲到顶部，碰到一条弧形导轨，被顺滑地"带弯"——像坐滑梯，是一点点转过去的，不是一瞬间横甩。所以你看到的是"滑过导轨逐渐转向"，而不是"刚开始就突然横向移动"那种违和感。

第三段：自由落体

转完弯，球就像抛出去的石子，纯靠重力穿过钉子阵、自然落进九个格子之一。这一段没有助推、没有刹车、没有牵引，落到哪就是哪。

为什么分三段？

因为"转变得自然"比什么都重要。如果球在一帧里突然横移，玩家一眼就会觉得假；如果全程有人偷偷拽着球走，玩家迟早会发现"球不该那么走"。三段式让每一个动作都有清晰的物理原因——上升是发射、转弯是导轨、下落是重力，每一步都能用眼睛看懂。

没人帮球作弊

离手后全凭重力 + 碰撞，落到哪算哪，你看到的就是真的

零穿帮
球落进哪格，结算就是哪格 · 没有预判 · 没有预演 · 没有偷偷换盘面

你只管丢，剩下交给物理

就像往一个装满钉子的斜槽里丢一颗玻璃珠——你只管丢，之后每一跳、每一滚、每一次撞钉子，都是它自己撞出来的。没人伸手去拨它，落到哪个口子就是哪个口子。公平到不耍赖，这是这台机器最大的诚意。

卡住也不玩消失

万一球真的卡在某个角落一动不动（大约 1 秒多），系统不会让它消失重来——而是轻轻推它一下，打破死循环让它继续掉；最多推十次，再不动才悄悄结算。玩家永远看不到"重来"，只会看到球突然往下掉了。

让程序自己养出公平

九个格子要落得一样匀，背后有几百个要调的旋钮——机器自己试了几十万次，一代代养出最公平的组合

会自己进化的调参

几百个"旋钮"要调，人一个一个试，一辈子也试不完。于是作者不自己调——写了一个"会自己进化"的程序：像养鱼一样，每代只留落点最匀的那批当"爹妈"，杂交、变异、生下一代，一代代淘汰差的、留下好的，几十代之后自动长出一套最公平的旋钮组合。这台机器的公平，是机器自己"养"出来的，不是人手搓出来的。

4 个看不见的旋钮

这台机器有 4 个旋钮：球进场的角度、进场的力气、撞天花板的角度、撞天花板的力气。每个旋钮都不是固定一格，而是好几档、每档命中概率不一样，还按你按的力气分十档各配一套——像一台调音台，你使多大劲，旋钮就转到哪一组。

力度互补：九个格子个个有机会

轻轻按，球进场偏右边；按满，球偏左边；中间各种力气，把九个格子自然铺满。不是每一档都强行平均（那会互相打架），而是"你随便用多大劲，长期看九个格子都平均"。没有一个格子被冷落。

天花板也成了一台弹射器

以前球撞到天花板只是"啪"地弹回来；现在天花板也变成了一台弹射器——撞上去会按角度转一下、按力气缩一下，但保证球一定往下走，绝不"吸"在天花板上反复磨蹭。撞顶这个原本最无聊的动作，现在也成了可控的小设计。

"不用 1 像素糊弄人"的硬指标

作者定了一条死规矩：球撞钉子后必须肉眼真的弹起来——看得见弹起来的球要占四分之一以上，最高又不能弹得太夸张。像捏真弹簧那样"弹过头再回来"，而不是代码里假装的那么一下。随机只保证"你猜不到下一颗落哪"，平均则靠几十万次飞行标定出来——这两件事，作者分得很清。

游戏会说话

中几倍、返多少，都用人的声音报给你，一句不乱、永不抢话

51 条神经合成语音

中奖报数、余额不足提醒、轮次结束总结、返奖比例和投入切换也有语音提示——四档返奖率切换个个有声音，没有静默死角。听感像真人的温柔女声（XiaoxiaoNeural 音色）离线预录，22050Hz 高保真。

语音档也能听出中了多大

中奖音分5档递增：x2只有3个音，像小铃铛；x3加一音，x5再加一音，x10加低音支撑（像管风琴踏板），x20加到7个音+碎星收尾——像教堂钟声。混响逐渐加深，声场逐渐"撑开"。

全局语音互斥

上一个语音没播完，新按钮语音直接不出声。你快速连点两个按钮，只听到第一个——两个播报不会叠在一起变成一团浆糊。

36 种音效，0 个文件

弹跳、碰撞、入袋、中奖——全部由代码实时生成。其中 6 种撞钉声的音高恰好构成一个全音阶——任何两个音叠在一起都不会刺耳。球下落时随机撞钉，每次触发的音高不同、节奏不同，但无论怎么排列都是天然和谐的旋律，像在听一段每次都不一样的即兴音乐。

四层后备，绝不哑火

Android 原生硬件混音 → 电脑多声道直写声卡 → 软件兜底 → 静音模式不崩溃。任意一层坏了自动切下一层，玩家永远听得到声音。

"棘轮声越来越急、弹簧变金黄、发射咔哒一声伴随轻微震动、球撞钉子叮叮当当、入袋咚+弹跳、语音报结果——视觉、听觉、触觉从未同时缺席。每一步操作都有确认，每一个状态都有声音。"— UX 专家评审

有温度的刹车

不是冷冰冰踢你出去，而是像完成一局棋一样有仪式感

每轮 N 次，打完自动停

每轮20、50或100次可选。打完后弹出总结窗口+语音播报完整报数，可点"确定"快速结束，自动重置。用"恭喜完成一轮挑战"替代"你已被限制"。

跨启动持久化

余额、已玩次数、命中率全部存下来持久化。杀进程重开不会重置——防沉迷机制真正有效。打满后重启自动静默重置，不会卡在"本轮已结束"弹窗。

哑火零损失

手指滑了、没按到位？不扣珠子、不计次数、不换盘面。想练多少次就练多少次，零损失。新手不需要一次就学会。

藏在毫厘里的用心

那些你可能永远不会注意到、但少了就会觉得"差点意思"的东西

发射震动 + 音量分级

柱塞释放瞬间14ms 微震（哑火 8ms），配合发射音效按力度分级。满蓄力和刚过阈值的发射声不再一样——蓄力的听觉回报完整回归。

钉子受击闪金光

球撞到钉子时，那颗钉子会"叮"地闪一下金光、微微鼓一下，300 毫秒后慢慢弹回原样。你每一次撞钉都有视觉反馈，球越活跃，钉子阵越"活"。

落地弹跳：球真的在弹

球落入槽位后弹跳3~4次才停住，弹跳系数随机变化避免机械重复。落地有金属锁扣声、弹跳有金属叮声。不再瞬移到槽中心——球停在哪就停在哪，自然得不像代码。

飞行中统一灰化

球在飞时，所有按钮+标签文字统一灰化——返还比例、投入设置、统计文字全部变暗。只有弹珠数字和状态提示保持亮色。视觉层级一目了然：现在不是操作的时候，看球就行。

关声音可以反悔

点"关闭声音"后，系统先播完提示语音才真关——延迟1秒。在这1秒内切回来，关闭自动取消。重启后声音状态与按钮显示一致，不会"看着是关的实际在响"。

呼吸 + 返回键保护

入袋"咚"和中奖语音之间有一小段刻意沉默。Android返回键被拦截——误触不会退出，整局进度不会清零。好的声音不是塞满每一毫秒，好的交互不是多一个退出路径。

两个平台，一颗心

电脑手机共用同一套物理和声音，一个字不改——还能自己给自己跑分

单事实源 + 代码生成

PC 版是物理/音效/数学的唯一事实源。Android 版由构建脚本从 PC 版原样抽取纯逻辑段 + 拼接手写界面段生成——物理代码一个字都不改，杜绝手抄千行出错的系统性风险。

GitHub Actions 云构建

push 到 main → 自动出 APK。锁定版本组合，首次构建 20 分钟，缓存命中后 3 分钟。全程不需要本地装 Android SDK。

性能自己会证明

长按标题"跳跳的弹珠机"3 秒 → 所有按钮灰化 → 先真实采样屏幕帧率（自动发 3 发球），再后台跑物理模拟（每次 0.7 秒、连跑 5 次取中位，短时长不触发手机降频）→ 弹窗显示设备型号、运算速度（每秒多少步）、每次发射耗时、平均帧率、1% 低帧率。PC 和手机都支持，是骡子是马拉出来遛遛。自测四万次飞行验证返奖率精确、落袋零穿帮、回弹感达标。

横着拿，也只给你竖屏

一台联想平板引发的"屏幕保卫战"——十几版提交、截图像素取证，才让画面永远是你熟悉的样子

四方向跟着手转

正着拿、倒着拿 180°、左横、右横——四个方向全跟重力感应。倒着拿画面自动翻正，左边横过去和右边横过去，画面各自认得方向，永远正对你。

横拿时画面纹丝不改

平板横过来的瞬间，画面还是竖屏时那个样子——构图、大小、方向全不变，整屏铺满。玩家扭头看一眼，或把平板转回竖着继续玩。不做左右分栏，也不缩成小竖条。

和系统"抢方向盘"

联想大屏系统只认应用"正在说"的方向请求，不读安装清单里的声明——而游戏引擎每次启动都会自报"我是竖屏游戏"，于是被塞进半屏小盒。解法是每 0.7 秒大声纠正一次"我四个方向都行"，转屏瞬间再立刻喊一遍，抢回话语权。

手指和弹窗都跟着转

画面整体旋转 90° 后，手指坐标做逆变换——点哪是哪，蓄力、发射、长按标题呼出跑分全部跟手；所有弹窗挂进旋转层，跟着画面一起转，不会横着飘出去。

十几版提交换来的三个教训

① 大屏系统上"锁竖屏"不是"屏幕不转"，而是"被塞进小窗"——死路；② 声明写在安装清单里没用，这台系统只认运行时的请求，谁最后开口听谁的；③ 定位问题别猜——截图像素取证 + 屏上诊断小字，一次锁定"系统到底给了多大的窗户"。最终方案四件套缺一不可：现代版本标签 + 清单声明 + 运行时守卫 + 反旋转层。

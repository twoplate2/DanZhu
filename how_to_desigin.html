一根弹簧的自我表达

在弹珠机里，你能"看见"自己用了多大力——而且是真实的物理回弹

眼睛代替数字

力度条是"仪表盘思维"。弹簧是"身体思维"——你看见它被压缩，本能就知道力量有多大。看颜色就知道力度，不需要识字、不需要说明书。

真实物理回弹

松手后弹簧不是线性滑回原位，而是阻尼振荡——过冲到-0.25倍率再回弹，3~4个可见周期后平稳停下。就像捏一根真正的弹簧，释放后它会"弹过头再回来"。零张图片，每个像素都是算出来的。

三种颜色，三个故事

灰蓝色 = 还没用力 金黄色 = 正在蓄力，越来越"烫" 橙红色 = 力度不够，弹不上去。满蓄力后持续按住不再是死寂——每0.6秒轻响一声"还顶着"的确认音，消除"是不是没在蓄力了"的疑惑。

当游戏开始说话

50条真人语音 + 36种代码合成音效 + 全局语音互斥 = 永远不抢、永远不乱

50条真人语音

中奖报数（15种金额全覆盖）、余额不足提醒、轮次结束总结、返奖比例和投入切换也有语音提示。温柔女声 XiaoxiaoNeural 预录，22050Hz高保真。

语音档也能听出中了多大

语音模式下中奖不只念数字——win琶音以自适应闪避混入语音文件：琶音在语音开口前起势（档位递增增益0.42→0.22），检测到人声后60ms内压到0.08底线。x2和x20的听感差异完整保留。

全局语音互斥

上一个语音没播完，新按钮语音直接不出声。你快速连点两个bet按钮，只听到第一个——"返还比例百分之八十返还比例百分之一百"不会叠在一起。

弹跳、碰撞、入袋、中奖——全部由代码实时生成。正弦分音+噪声瞬态+梳状混响，固定种子保证每次音色一致。全部11.7秒素材约0.35秒合成完毕，比加载一张图片还快。

Android SoundPool原生硬件混音 → winmm多声道直写声卡 → Kivy SoundLoader纯软件兜底 → 静音模式不崩溃。任意一层坏了自动切下一层，玩家永远听得到声音。

数学站在你这边

发射前预判轨迹、结果由概率决定、物理只管表演——每一发都在计划之内

结果提前算好，物理只管表演

每颗球的落点在发射前就按概率选好，物理引擎只负责生成可信的弹跳轨迹。你看的每颗球都是"真的在弹"——但数值始终精确可控。不是"调倍率赌运气慢慢收敛"，是每一发都在计划之内。

发射前预判：不让你看到"卡住"

松手瞬间，系统用21毫秒快速模拟完整飞行轨迹。如果这条轨迹会卡死，后台静默换一个盘面重算。用户永远只看到一次流畅飞行，不知道后台已经换过。

差一点就中了！

弹珠机最强的情绪钩子——纯表演，不动RTP，但心跳加速

诱饵偏移：朝高倍槽"滑过去"

如果目标槽的邻槽倍率更高，球在钉阵中段会被故意推向高倍槽方向偏移40像素，碰到隔板"咔"一声——玩家心脏一紧。然后弹簧把球拉回真实目标槽，有惊无险。结算永远是预定槽，RTP分毫不差。

致死保护：慢了就撤

球竖直速度低于150px/s时立即撤销诱饵——卡死的球vy必然接近零，撤销后回到已验证零卡死的引导路径。这三个参数是n=3000真实盘面扫出来的，不是猜的。

卡死重掷：看不见的安全网

万一球真的卡住（位置不动超1.2秒），系统自动把球退回柱塞、按原力度重飞——落点不变、RTP不变、不重复扣珠。最多重试2次，玩家最多看到"球卡了一下重新飞"，比"定住4秒再凭空结算"优雅得多。

防沉迷，但有温度

不是冷冰冰踢你出去，而是像完成一局棋一样有仪式感

每轮N次，打完自动停

每轮20、50或100次可选。打完后弹出总结窗口+语音播报完整报数，自动重置。用"恭喜完成一轮挑战"替代"你已被限制"。

跨启动持久化

余额、已玩次数、命中率全部存JSON持久化。杀进程重开不会重置——防沉迷机制真正有效。打满后重启自动静默重置，不会卡在"本轮已结束"弹窗。

哑火零损失

手指滑了、没按到位？不扣珠子、不计次数、不换盘面。想练多少次就练多少次，零损失。新手不需要一次就学会。

温度在细节里

那些你可能永远不会注意到、但少了就会觉得"差点意思"的东西

发射震动 + 音量分级

柱塞释放瞬间12ms微震（哑火8ms），配合发射音效按力度分级（0.60→0.80增益）。满蓄力和刚过阈值的发射声不再一样——蓄力的听觉回报完整回归。

落地弹跳：球真的在弹

球落入槽位后弹跳3~4次才停住（恢复系数0.42），弹跳系数±8%随机变化避免机械重复。不再瞬移到槽中心——球停在哪就停在哪，自然得不像代码。

中奖大字活满3秒

金色"+50"大字缩放弹入（1.5s）→ 静止展示（1.5s）→ 淡出，完整3秒生命周期。不会被盘面刷新意外清除，手机端font_size仅值变时写一次（144次→10次），流畅不掉帧。

飞行中统一灰化

球在飞时，所有按钮+标签文字统一灰化——返还比例、投入设置、统计文字全部变暗。只有弹珠数字和状态提示保持亮色。视觉层级一目了然：现在不是操作的时候，看球就行。

关声音可以反悔

点"关闭声音"后，系统先播完提示语音才真关——延迟1秒。在这1秒内切回来，关闭自动取消。重启后声音状态与按钮显示一致，不会"看着是关的实际在响"。

130毫秒的呼吸 + 返回键保护

入袋"咚"和中奖语音之间有0.13秒刻意沉默。Android返回键被拦截——误触不会退出，整局进度不会清零。好的声音不是塞满每一毫秒，好的交互不是多一个退出路径。

合成引擎

5档中奖琶音递增

x2→C5-E5-G5大三和弦(0.72s)，x3→4音(0.85s)，x5→5音(1.00s)，x10→6音+130.8Hz低音支撑，x20→7音到C7+82Hz低音+碎星收尾(1.40s)。混响0.14→0.32递增，声场逐渐"撑开"。

撞钉音配方（_sfx_tink）: 非谐分音 (1.00, 2.01, 3.42) × 基频1040~1880Hz + 0.004s噪声瞬态(lp=0.60) → _pack归一化到peak 0.72 发射音配方（_sfx_launch）: 0.01s白噪声柱塞机械声 + 640→150Hz扫频弹簧声(0.28s, tau=0.16) + 3阶分音共鸣(tau=0.22) → _pack归一化到peak 0.58 数字朗读引擎（number_voice_names）: 1250 → ["voice_d_1","voice_u_1000","voice_d_2","voice_u_100","voice_d_5","voice_u_10"] 片段间5ms间隙依次Clock.schedule_once排队播放，支持"二/两"变体规则

附录C：RTP数学与验证

choose_target算法

非零格均值=sum(reward)/len(reward)，命中概率w=min(1,rtp/均值)。E[目标倍率]=w×均值=精确rtp。奖励值分布：55% x2 → 25% x3 → 13% x5 → 5.5% x10 → 1.5% x20（E≈3.35）。盘面保底非零格：80档≥2，100档≥4，120档≥6。

自测门禁系统

n=40000次飞行（标准误≈0.015，门禁±0.05）。6项门禁：RTP偏差→引导命中>90%+卡死=0→哑火500发零泄漏→near-miss零越格→蓄力区分度≥50px+首钉80~95帧→音效体检0异常。一部手机大小，跑完约0.4秒。

choose_target推导: w = min(1.0, rtp / mean_r) — 命中奖励格的概率 零格集Z = {i | mult[i]==0}, 奖励格集R = {i | mult[i]>0} if Z非空 and random() > w: return random.choice(Z) — 故意不中 else: return random.choice(R) — 命中，倍率由roll_multipliers分布决定 E[payout] = w × E[reward_value] = w × 3.35 = rtp (当rtp ≤ 3.35时) 三档均满足 rtp ≤ 3.35，所以公式精确成立。
